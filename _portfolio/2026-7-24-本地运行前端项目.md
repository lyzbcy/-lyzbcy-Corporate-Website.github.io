## 1. 这个工具解决什么问题

接手每一个前端项目，为了本地测试，都要先搭一套本地预览环境——而这些预览脚本不能 git 上去（会被同事骂），所以需求一结束别人就用不了，下次自己重新接手还得重跑一遍，浪费时间和 token。

这个软件把这件事**固化成一个桌面 App**：装一次，统一管理所有前端项目，团队共享，永久在线。核心设计原则是**零文件侵入**——所有预览能力都在软件内部，绝不往用户的项目目录写任何文件。

## 2. 功能

- **自动识别项目类型**：静态站 / Vite / Next / Vue / CRA / Nuxt / Angular，选目录即判断
- **一键启动**：端口自动顺延、健康检查通过才开浏览器、先打开自动生成的目录页
- **目录页**：扫描项目页面，按栏目分类 + 搜索 + 紫粉童话风设计
- **网关端口管理**：一目了然看到本机在跑哪些预览，可单独停掉
- **AI Agent 接入**：本地 HTTP 接口 + Prompt，用自然语言控制启停
- **token 注入**：企微/CRM 类项目从测试环境搬 token 建立本地登录态
- **自动更新检查**：打开时比对 GitHub release

## 3. 技术栈

- **Electron 43** + 原生 JS（零构建，省 token）
- 内嵌静态预览服务器（读 `<base href>` 显式映射，正确处理相对路径）
- 框架项目走子进程 `npm run dev`，从输出抓真实端口
- 持久化用稳定 userData 路径，更新不丢项目数据

## 4. 🤕 技术难点与解决方案

**端口冲突（vite 绑 IPv6 dual-stack）**：vite 默认绑 IPv6 `::`（dual-stack），而端口探测只查 IPv4 `127.0.0.1` 会漏判，导致两个进程同端口 v4/v6 共存。解法：探测用 `0.0.0.0`（dual-stack 的 IPv6 socket 会接管 IPv4，所以能发现所有占用方式）。这个 bug 靠子 agent 用 lsof + 控制接口实测才定位。

**路径解析（`<base href>`）**：91% 的真实项目页面用 `<base href="/mobile/">` 改写相对路径，最初的"猜测式 prefix-strip"会在边界返回错误文件还报 200（比 404 危险十倍）。解法：启动时扫所有 html 的 base 前缀建显式映射表，请求按已知前缀精确匹配——对照 nginx 的 `alias` 语义。

**npm 吞端口参数**：`npm run dev --port 8091` 里 `--port` 被 npm 当成自己的参数，vite 收不到用了默认端口。解法：用 `--` 分隔符正确转发（`npm run dev -- --port 8091`）。

**userData 路径漂移**：`app.getPath('userData')` 依赖 `app.getName()`，打包后（productName）和开发时（package name）不一致，更新后项目数据"消失"。解法：固定稳定路径 + 自动迁移旧数据。

## 5. 开发流程的教训

这个项目最大的收获是**测试方法**：用造的临时目录测，全过但是假的（因为造的目录不含 `<base href>` 等真实特征）。后来改成用真实项目做端到端冒烟测试，并派无记忆子 agent 做对抗性审查，才发现多个隐藏 bug。
