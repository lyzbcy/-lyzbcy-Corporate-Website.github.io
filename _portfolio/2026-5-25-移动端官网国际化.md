## 1. 项目背景

一套没有前端框架、由几十个独立 HTML 页面组成的官网移动端站点，需要支持中英文双语切换，并且不能引入构建工具或第三方运行时依赖。真正的难点不在“把中文翻译成英文”，而在于：静态多页站点在没有 SPA 路由和构建打包的前提下，如何让所有页面的文字、图片、布局在两种语言间一致切换，且首屏不出现语言错乱。

项目分两阶段推进：第一阶段是主体开发与提测上线；第二阶段是上线后用户反馈的图片闪烁问题排查与统一修复。

## 2. 我负责的工作

- 独立设计原生运行时 i18n 方案，从首页英文样板和语言包结构起步，逐页铺到全部业务页面。
- 维护中英文语言包，完成 40+ 页面的声明式翻译标注和样式适配。
- 负责上线后的图片闪烁问题排查，写成完整闭环报告，并实施统一首屏修复。
- 出具多轮提测包与线上 hotfix 包，配合测试反馈持续修复内容漏翻和样式问题。

## 3. 技术方案

<ol class="project-flow">
  <li><strong>语言包</strong><br>每种语言一个 JS 文件，挂载到全局对象，按页面 / 模块分层组织 key。</li>
  <li><strong>声明式翻译</strong><br>HTML 元素加 data-i18n 属性，核心库统一批量翻译，业务代码无需感知当前语言。</li>
  <li><strong>动态 DOM</strong><br>用 MutationObserver 监听 body 子节点变化，新插入节点自动翻译，翻译期间暂停监听防递归。</li>
  <li><strong>首屏防闪</strong><br>在浏览器解析正文前确定语言并写入 html lang，英文页在翻译完成前保持隐藏。</li>
</ol>

格式化全部委托浏览器原生 Intl API，日期、数字、货币格式跟随当前语言自动切换，无需维护任何格式规则。整套方案零依赖、零构建，适合语言种类少且语言包体积不大的官网类项目。

## 4. 技术难点与解决方案

### 首屏图片从英文闪到中文（线上 P1）

线上反馈：移动端某案例页用手机打开时，部分背景图会先短暂显示英文版，再切换成中文版，手机网络越慢越明显。第一反应排查了图片缓存异常和服务器重定向，都不是。

顺着“为什么浏览器会先按英文渲染”这条线，对照 PC 版同类页面（PC 版不闪）定位到三个差异点叠加：页面初始 html lang 写成了英文、英文背景图的 CSS 规则在解析时立即触发、移动端国际化资源在页面显示之后才串行加载完毕。现有的防闪逻辑方向没错，但它到达页面的时机太晚——在首屏已经绘制之后才执行。

最终方案不是只改一个页面或加固定延时，而是对齐 PC 版已验证的策略，在发布包内统一实施“首屏语言先定、再绘图”的机制：所有中文原始页统一改回正确语言、在阻塞脚本最前面同步确定语言并写入 lang、英文页在替换完成前保持隐藏、再加 5 秒兜底恢复避免资源异常时页面永久空白。顺带补齐了 5 个漏接初始化脚本的页面。最终在手机视口下验证两种语言入口均不再闪。

### 提测包缺文件，中文页外露 key 字符串

测试环境上出现两个奇怪现象：首页中文模式直接显示 key 字符串、另一个案例首页英文模式整页仍是中文。第一反应怀疑绑定写错或初始化失败，对照源码发现都没问题。

转去查提测包本身的完整性，根因不在代码逻辑，而在出包时漏带了文件：一个页面引用的中文语言包没进包（英文包在，所以英文页正常、中文页外露 key）；另一个页面则是页面本体和它依赖的 CSS / JS / 图片整个没进包，测试环境还在用旧模板，所以英文模式也整页中文。补齐后把“页面引用了什么”和“包里实际有什么”做 diff 这条规则，沉淀成了专门的出包整理流程。

### 92 文件大改动如何降低漏改风险

一次内容修复 hotfix 改了 90 多个文件，覆盖多个页面和语言包，反馈又零散，纯靠人工逐文件 review 极易漏。最终用两种方式交叉验证：先做 AI 代码审查，再人工逐个对照；同时用脚本对每个页面做“逐元素精确判定”，找出所有含中文文本却没有任何翻译绑定的元素——这种元素切换语言时会原样暴露，是真正的漏网。

初版用的是“中文文案总数 vs 翻译节点总数”的粗糙比法，被用户随手一找就命中漏网，说明方法不可信；改成逐元素判定后推翻了初版结论，发现漏网远不止被指出的那几个。这条经验比修具体 bug 更值得留下：判漏网要精确到元素，不能数总数。

## 5. 项目复盘

纯静态多页项目的多语言，难点不在翻译本身，而在首屏时序和静态资源完整性。语言状态必须在首屏绘制前确定，否则再完善的防闪代码也挡不住已经画出去的那一帧。

大改动量的修复不能只靠人工 review，至少要配一种程序化的全量校验；而初版用粗糙方法给的“没问题”不可信，要敢于在拿到反证后推翻重来。这次最有价值的产出不是某个 bug 的修复，而是把“首屏防闪机制”“漏网逐元素检测”“出包完整性核对”这几件事固化成了可复用的团队流程。
