# docs 目录导航（渐进式披露入口）

> AI 开发时先读这个文件，按需再往下读，不要一次读完所有文档。

## 目录结构

| 路径 | 内容 | 什么时候读 |
| --- | --- | --- |
| `project.md` | 项目介绍、技术栈、目录结构、本地预览、分支与提交规范 | 第一次接手项目 / 不确定怎么跑起来 |
| `todo.md` | 当前 To-do list 与开发进度 | 每次开始工作前，确认要做什么 |
| `requirements/` | 按日期归档的需求文档（含文案、设计稿链接、验收标准） | 开发对应需求前必读 |
| `reference/homepage-banner.md` | 首页 banner 轮播的代码落点与改动套路 | 改 banner / 首屏宣传位 |
| `reference/i18n.md` | 中英文适配方案与注意事项 | 任何涉及文案的改动 |

## 使用规则

1. 改哪一块功能，就只读对应 reference + 最新需求文档。
2. 开发完成后更新 `todo.md` 的进度，并在 `project.md` 的版本记录里补一行（同步递增页面版本号 `?v=` 时记录）。
3. 需求上线后把 `requirements/` 里对应文档标注「已上线 + 日期」。
